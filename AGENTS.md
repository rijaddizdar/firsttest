# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- **Stage:** early prototype. `README.md` is the product spec (guide animal Penny the armadillo, the 13-level map, lesson flow, parent account model, privacy rules); update it when product decisions change. `App/` holds the SwiftUI app: welcome → grown-up setup → level map → a level's lesson list → lessons → code-locked parent dashboard. Progress is saved on the device (SwiftData); there is still no backend, sync, Sign in with Apple or consent flow. `MoneyPals.xcodeproj` (committed) opens and runs directly; it is generated by XcodeGen from `project.yml` — after adding/removing files in `App/`, run `xcodegen generate`. Two exceptions need no regeneration: `App/Content/` is a folder reference (lesson files are picked up as-is) and `Assets.xcassets` is a single file reference (new imagesets are picked up as-is). See `docs/RUNNING.md`.
- **Lessons are data, not screens.** Content lives in `App/Content/` (`curriculum.json` = worlds and levels; `lessons/<id>.json` = one lesson). The schema and every screen type are documented in `App/Lessons/LessonContent.swift`; `LessonDecoding.swift` validates on load and its errors name the file and the fix; `CurriculumLibrary` loads and answers map/progress questions; `LessonRunner` owns the README section 3 answer rules (glow, pop/wobble, badge, Penny pose, haptic on right only, and sending a missed question back later in the lesson); one view per screen type renders it. A level with `"lessons": []` shows "Coming soon" and never blocks later levels. Adding or rewording a lesson needs no Swift change. Lesson sounds are a documented stub (`LessonAudio`) until audio assets exist. **Two content limits are about the phone, not the maths:** "Sort it" and "Count it" each draw one row, so at most 4 pictures to sort and 8 coins in a pile (`SortItScreen.maxItems`, `CountItScreen.maxAvailable`) — over either is a load-time error.
- **World 1 is written; the level check is generated.** All 15 World 1 lessons are in `App/Content/lessons/`, and `docs/world-1-lesson-scripts.md` is the readable script of every one — **generated** by `docs/tools/generate_lesson_scripts.py`, so edit the JSON and re-run it, never that page. The per-level **lesson list** is `App/LevelLessonsView.swift` (route `.levelLessons`); tapping a level opens it rather than launching a lesson. The friendly end-of-level **check** has no content file: `App/Lessons/LevelCheck.swift` builds `level-<n>-check` from the level's own questions (one per lesson in turn, four in all), it plays through the normal player, it cannot be failed, and a level counts as complete only once it is done.
- **A child's profile picture is drawn, never uploaded.** `App/Avatar/` holds the five choices (`Avatar.swift`), the layered SwiftUI drawing (`AvatarArtwork.swift`) and the shared "Make it yours!" builder (`AvatarBuilderView.swift`). Everything is laid out in a fixed 100x100 design space and scaled, so the 40pt dashboard badge and the 96pt picker tile are one picture; `AvatarBadge` is the only way to show a kid. Its palettes (skin, hair, scarf) sit beside `avatarChoices` in `Theme.swift`. A child's own first time — name, builder, meet Penny — is `KidFirstRunView.swift`, run from "Who's learning?" while `Kid.hasFinishedFirstRun` is false.
- **Persistence:** `App/Persistence/` only. `Records.swift` holds the SwiftData models; `ProgressStore.swift` is the only code that reads or writes them, and `AppState` is the only thing that calls it — screens render the `Kid` value type and never touch SwiftData. There is no migration plan, so a new `KidRecord` field must be OPTIONAL and be given its default when the record is mapped to `Kid` (see how the avatar fields load). Store only what `README.md` section 9 allows; the parent code is a salted SHA-256 hash, never plain text; time-per-day is pruned to a 90-day window.
- **Visuals follow the Penny Design System.** `App/Theme.swift` transcribes its tokens literally (palette, type roles, `Radius`/`Border`/`Motion` constants); reuse those constants rather than hard-coding numbers. Hard brand rules: no green lead, no red anywhere, streak icon is a coin (never a flame), flat cream backgrounds (the peach-50% map header is the only tinted band; Penny's speech bubble is the only shadow). Reward/level/answer art are **Fluent Emoji 3D** PNGs in `Assets.xcassets/Icons` via `FluentIcon` — add one by dropping a 256x256 `<kebab-name>.imageset/` in there (licence in `App/Resources/FLUENT-EMOJI-LICENSE.txt`, credited in the parent area); UI chrome with no Fluent equivalent stays on SF Symbols. Penny renders from placeholder pose images in `Assets.xcassets/Penny` (`PennyView`), pending the commissioned 3D character.
- **Audience is children (6–11):** all kid-facing copy must follow the language and tone rules in `README.md` section 7.
- **Kids Category and COPPA constraints are hard rules:** no third-party analytics, advertising or tracking SDKs, no IDFA, and no child data beyond the table in `README.md` section 9. Only the parent signs in (Sign in with Apple is unavailable under 13).
- **Planned stack:** SwiftUI iOS app (see `README.md` section 8). Full Xcode 27 is installed: build with `xcodebuild -project MoneyPals.xcodeproj -scheme MoneyPals -sdk iphonesimulator -destination "generic/platform=iOS Simulator" build`. Guard iOS-only APIs with `#if canImport(UIKit)` / `#if os(iOS)` so the code also type-checks against the macOS SDK. The **iOS 27 simulator runtime is installed** (iPhone and iPad devices present): boot with `xcrun simctl`, install the built `.app`, and drive screens for screenshots via the `UITEST_*` env vars (pass through `SIMCTL_CHILD_*`) — `UITEST_STORE` (`memory` / `reset` / `disk`), `UITEST_SEED=demo`, `UITEST_KIDS`, `UITEST_ROUTE`, `UITEST_LEVEL`, `UITEST_LESSON`, `UITEST_LESSON_SCREEN`, `UITEST_LESSON_FEEDBACK`; they are listed in `docs/RUNNING.md`. A run that seeds kids defaults to a throwaway store, so screenshots never write into real progress. Cold-launch renders need a generous settle (~6–9s) before `simctl io screenshot`, or you capture a blank frame.
- **App name is intentionally absent** from all code/UI pending a trademark search; the `@main` type `MoneyPalsApp` is a placeholder only.
